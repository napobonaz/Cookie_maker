1. Overview of the Tool

This web application provides a user-friendly interface to convert your 2D SVG vector graphics into 3D printable cookie cutter STL files. It leverages powerful libraries to automate complex design tasks, including:

  • Scaling: Automatically scales your design to various target sizes, ensuring your cutter is the perfect fit.
  • Wall Generation: Creates the precise cutting edges and sturdy support walls based on your specified thickness and height.
  • Base Creation: Adds a robust base to the cutter, providing stability and ease of use.
  • Internal Cutout Management: Intelligently identifies internal cutouts (holes) within your design. You can define a threshold to either preserve these as cutouts or fill them in, which is particularly useful for small, delicate details that might otherwise break during printing or use.
  • Structural Bridging: Automatically generates internal and external structural bridges to connect disconnected parts of your design. This ensures the final cutter is a single, strong, and robust piece, preventing breakage.
  • Visual Previews: Generates immediate visual feedback with both 2D and 3D PNG images of the generated cutter. These previews show the walls, base, and how internal cutouts are handled, along with their calculated areas, allowing you to verify the design before printing.

2. Preparing Your SVG File in Inkscape (Crucial Steps!)

Proper SVG preparation is the most critical step for successful STL generation. Follow these detailed steps in Inkscape before uploading your SVG to the web interface:

2.0. Recommended Inkscape Workflow:

For best results, follow this design and preparation workflow in Inkscape:

  1. Design Outline: Create your primary outline shape with a fill color but no stroke. This will form the main cutting edge of your cookie cutter.
  2. Internal Contours: For any internal closed contours (holes, inner details), create them using available shapes (e.g., circles, rectangles) or drawing tools. These should also have a fill and no stroke initially.
  3. Recreate Internal Lines as Spline (Optional but Recommended): For internal lines or details that are not closed contours but should be part of the cutter's structure (e.g., details that are extruded as walls), recreate them as splines if they are currently simple lines. This ensures they are treated as paths.
  4. Convert All to Paths: Select all objects in your document (Ctrl+A). Then, convert them to paths by going to Path > Object to Path (Shift+Ctrl+C). Repeat this step if you have nested groups until all elements are individual paths.
  5. Resize Page to Content: With everything still selected, adjust the document size to fit your design precisely. Go to File > Document Properties, and under the "Custom size" section, click "Resize page to drawing or selection". This helps normalize the SVG's coordinate system.
  6. Break Apart Vectorized Sections (if applicable): If you have vectorized pixel graphics (e.g., from a bitmap trace) that result in multiple overlapping or grouped paths, select them and use Path > Break Apart. This separates complex paths into simpler, distinct components, which can be crucial for correct cutout detection.
  7. Apply Transforms: This is a critical step! With all objects selected, use the "Apply Transforms" extension. Go to Extensions > Modify Path > Apply Transforms. Run this extension to bake all scaling, rotation, and translation directly into the path data, ensuring absolute coordinates. If you don't have this extension, it's highly recommended to install it (e.g., from GitHub).
  8. Save as Optimized SVG: Finally, save your file as an "Optimized SVG" (File > Save As..., choose "Optimized SVG" from the dropdown). This removes unnecessary metadata and ensures a clean, parsable SVG structure.

2.1. Convert All Objects to Paths:

SVG files can contain various object types such as rectangles, circles, ellipses, polygons, text, and grouped objects. For the script to correctly interpret your design, all these elements must be converted into fundamental path elements.

  • Action: Select all objects in your Inkscape document. You can do this quickly by pressing Ctrl+A or by navigating to Edit > Select All.
  • Next, go to Path > Object to Path (keyboard shortcut: Shift+Ctrl+C).
  • Note: If your design includes grouped objects, this conversion might not apply to elements nested within groups. You may need to **Ungroup** them (keyboard shortcut: Shift+Ctrl+G) repeatedly until all elements are individual objects, then re-apply "Object to Path" to ensure everything is converted.

2.2. Convert Strokes to Paths (Especially for Text):

If your design uses outlines (strokes) rather than filled shapes (e.g., text with only an outline, or a line drawing), the script needs these strokes to be converted into actual filled paths. This transforms the stroke's visual thickness into a defined shape.

  • Action: After ensuring all objects are paths (from Step 2.1), select all objects again.
  • Then, go to Path > Stroke to Path. This action will create a new filled object that represents the outline of your original stroke.
  • Important for Text: If your design includes text, first convert the text objects into path objects using "Object to Path" (Step 2.1). Then, apply "Stroke to Path" to convert the outline of the letters into a distinct filled path.

2.3. Apply Transforms:

Inkscape, like many vector graphics software, can store transformations (such as scaling, rotation, or translation) as attributes applied to an object, rather than directly modifying the object's underlying path coordinates. If these transforms are not "baked" into the path data, the Python script might interpret the original, untransformed path, leading to incorrect scaling, positioning, or distorted shapes in your generated STL.

  • Action: This is a critical step to ensure accuracy! It's highly recommended to use the "Apply Transforms" extension within Inkscape. If you don't have this extension installed, you can typically find it on GitHub (e.g., https://github.com/Klowner/inkscape-applytransforms).
  • In Inkscape: Go to Extensions > Modify Path > Apply Transforms. Run this extension. This process will bake all transformations directly into the path data, making the SVG explicit about the final shape.
  • Verify: After applying transforms, you can select an object and examine its properties in the Inkscape XML editor (Edit > XML Editor) or object properties panel. The x, y, width, height attributes should now reflect the actual dimensions of the transformed object, rather than just the original dimensions with a separate transform attribute.

2.4. Save as Plain SVG or Optimized SVG:

Saving your file in a clean SVG format helps ensure the script can parse it without issues from extraneous metadata or complex Inkscape-specific elements.

  • Action: Go to File > Save As... and from the "Save as type" dropdown, choose either "Plain SVG" or "Optimized SVG". "Optimized SVG" is often preferred as it removes unnecessary metadata, resulting in a cleaner and smaller file.

3. Using the Web Interface (GUI)

The application provides a straightforward web interface for generating your cookie cutters. Follow these steps:

3.1. Main Page (index.html)

On the main page, you will find a form to upload your SVG and configure the cutter parameters:

  • Upload SVG File: Click "Choose File" to select your prepared SVG file. (See Section 2 for SVG preparation).
  • Wall Thickness (mm): Sets the thickness of the cutting walls. A common value is 0.75mm for good strength and sharp edges.
  • Wall Height (mm): Defines the total height of the cutting walls. This is the height of the inner cutting edge.
  • Outer Wall Height (mm): Sets the height of the outermost wall (the one that forms the overall shape of the cutter). This is often set slightly lower than the inner walls to create a comfortable grip and make it easier to press.
  • Base Thickness (mm): Determines the thickness of the solid base plate of the cutter. This provides stability to the entire structure.
  • Base Margin (mm): Controls how much the base extends horizontally beyond the cutting walls. A larger margin provides more stability and a larger surface area for handling.
  • Curve Resolution (mm): Affects the smoothness of curves in the generated STL. Smaller values (e.g., 0.1) result in more points along curves, leading to smoother curves but larger STL file sizes and longer processing times. Larger values (e.g., 0.5) create more faceted curves but smaller files.
  • Internal Bridge Density (0.0-1.0): Controls how many internal support bridges are added between disconnected inner parts of your design (e.g., connecting the inner loop of an 'O' to its outer loop). A value of 0.0 adds only essential bridges (minimal connections to ensure a single manifold mesh), while 1.0 adds many more for maximum structural stability.
  • Outer Bridges per Inner Poly: Specifies the minimum number of bridges connecting each inner "island" (a distinct, closed inner shape like the hole in a letter 'O' or a separate inner detail) to the main outer perimeter of the cutter. This ensures inner elements are well-supported.
  • Target X Sizes (mm, comma-separated): Enter a comma-separated list of desired widths (X-dimension) for your cookie cutter. The application will generate a separate STL file and corresponding preview images for each specified size. Example: 60, 80, 100.
  • Reference Cutout Infill Threshold (mm² for 80mm cutter): This is a crucial setting for managing small details. Any internal cutout (hole or inner shape) with an area smaller than this threshold (in square millimeters) will be filled in the final STL, making it a solid part of the cutter. This value is applied to the 80mm reference size.
  • Enable Proportional Scaling of Cutout Infill Threshold: If checked, the "Cutout Infill Threshold" you set for the 80mm reference cutter will be proportionally scaled for other cutter sizes. This helps maintain consistent detail handling across different sizes (e.g., a tiny hole that should be filled on a large cutter will also be filled on a scaled-down version). If unchecked, the exact threshold you entered will be used for all generated sizes.

3.2. Results Page (result.html)

After clicking "Generate Cookie Cutter", you will be redirected to the results page. Here, you will see:

  • Cutter Dimensions: The generated width, height, and total height of each cutter.
  • 2D Cutter Preview: A 2D PNG image showing the top-down view of your cutter.
    • Light Gray Area: Represents the outer base.
    • Black Lines: Show the cutting walls.
    • Red Filled Areas: Indicate internal cutouts that were smaller than your threshold and have been filled.
    • Transparent Areas with Green Dashed Borders: Indicate cutouts that were larger than the threshold and remain as holes.
    • Area Labels: Each cutout will have its area (in mm²) displayed, helping you verify the infill behavior.
  • 3D STL Preview: A 3D PNG image showing an isometric view of the generated STL model. This gives you a quick visual of the 3D structure.
  • Download STL Button: Click this button to download the generated .stl file for 3D printing.

Go Back (This button returns you to the main page.)

3.3. Where are the files saved?

When you upload an SVG and generate STL files, the application temporarily stores files on the server:

  • Uploaded SVG: Your original SVG file is temporarily saved in the `uploads` directory on the server. This file is automatically removed after processing to keep the server clean.
  • Generated STL and Preview Images: The resulting .stl files and the .png preview images (both 2D and 3D) are saved in the `output` directory on the server. These files remain there until manually cleared or the server is restarted. You can download them directly from the results page.

4. Troubleshooting Tips

  • "No valid paths found in SVG." error:
    • Cause: Your SVG file likely contains objects that are not paths, or the paths are empty/degenerate.
    • Solution: Re-check Step 2.1 and 2.2 in "Preparing Your SVG File in Inkscape". Ensure all objects are converted to paths and strokes to paths.
  • "Combined SVG outline has zero or near-zero width, cannot scale." error:
    • Cause: The overall bounding box of your SVG design is extremely small or has no width/height, often due to unapplied transforms or very small elements.
    • Solution: Re-check Step 2.3 in "Preparing Your SVG File in Inkscape" (Apply Transforms). Also, ensure your design is not accidentally tiny or consists only of single points.
  • Cutouts not filling/filling incorrectly:
    • Cause: The `Cutout Infill Threshold` might be too high or too low, or proportional scaling is affecting it unexpectedly.
    • Solution: Adjust the `Cutout Infill Threshold` on the main form. Review the preview images carefully to see the effect. If proportional scaling is enabled, consider unchecking it to use a fixed threshold.
  • Cutter looks thin/flimsy or too thick:
    • Cause: `Wall Thickness` or `Base Thickness` parameters are not suitable for your printer or desired strength.
    • Solution: Adjust `Wall Thickness` and `Base Thickness` on the main form. Typical wall thicknesses for cookie cutters are between 0.6mm and 1.0mm.
  • Jagged edges on curves:
    • Cause: `Curve Resolution` is too high (value is too large).
    • Solution: Decrease the `Curve Resolution` value on the main form. This will generate more points along curves, making them smoother, but will also increase processing time and STL file size.
  • Disconnected parts or weak connections:
    • Cause: The `Internal Bridge Density` or `Outer Bridges per Inner Poly` might be too low, or your design has very thin connections.
    • Solution: Increase `Internal Bridge Density` to add more internal support bridges. Increase `Outer Bridges per Inner Poly` to ensure more connections between inner islands and the outer wall. You might also need to manually thicken very thin parts of your design in Inkscape.

5. Further Customization (Advanced Users)

For users familiar with Python and the underlying libraries, the `app.py` script is well-commented, allowing for deeper modifications:

  • Adjusting Bridge Parameters: Experiment with the exact values for bridge widths within the `app.py` code if the GUI parameters are not sufficient.
  • Adding More Sizes: While the GUI allows multiple sizes, you can modify the `target_x_sizes` list directly in the `app.py` script for custom batch processing.
  • Implementing Complex Logic: The modular structure of the code allows you to delve deeper and modify aspects like dynamic wall heights for specific sections, or implement more complex infill logic based on shape characteristics.
